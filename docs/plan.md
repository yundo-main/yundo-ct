# 클래식 Windows 그림판 모방 프로젝트 계획

> **정리 (2026-11-13)**: 실제 구현은 tkinter가 아니라 **PySide6**(Qt)로 진행 중이다.
> 아래 1~7절의 `tkinter`/`Canvas` 표기는 초기 계획이며, 현재 상태와 변경 이력은 [devlog.md](devlog.md),
> UI 점검 내역은 [ui-checklist.md](ui-checklist.md)를 따른다.
> 개발 문서는 `docs/`(서버 API는 `docs/server-api.md`), 소스는 `paint-rs/`(그림판, Rust+Tauri), `server-rs/`(Rust 서버), `web/`(브라우저 화면)로 분리하고, 이전 Python 코드(PySide6 그림판 `app/`·`main.py`·`tests/`·`assets/`, 파이썬 서버 등)는 `legacy/`에 보관한다. 아래 계획·경로는 PySide6 시절 기록이다.

## 1. 목표

Python으로 클래식 Windows 그림판의 단순하고 직관적인 사용성을 재현한다.
초기 버전은 이미지 생성·편집·저장에 집중하고, 이후 기능을 단계적으로 확장한다.

## 2. 개발 방향

- 기본 GUI: ~~`tkinter`/`ttk`~~ → **PySide6** (macOS Python에 tkinter 미포함)
- 그림 영역: ~~`tkinter.Canvas`~~ → Qt 커스텀 캔버스 위젯
- 이미지 처리 및 파일 변환: `Pillow`
- 실행 대상: 우선 Windows, 가능하면 macOS/Linux도 지원
- 설계 원칙: 작은 기능부터 완성하고 각 단계마다 실행 가능한 상태 유지
- 외부 서버나 데이터베이스 없이 로컬 파일로 동작

## 3. 1차 완성 범위(MVP)

### 화면 구성

- 제목 표시줄과 메뉴: 파일, 편집, 보기, 이미지, 도움말
- 도구 상자, 전경색/배경색 표시 영역, 색상 팔레트
- 중앙 캔버스와 스크롤바
- 상태 표시줄(현재 도구, 좌표, 이미지 크기)

### 필수 도구

- 연필, 브러시, 직선, 사각형, 타원, 둥근 모서리 사각형, 다각형
- 지우개, 색 채우기, 색 선택, 텍스트 입력
- 확대/축소

### 파일 기능

- 새 이미지, 열기, 저장, 다른 이름으로 저장
- 종료 전 저장 여부 확인
- 편집 취소/다시 실행

# 강의도구 기능
## 기존 그림판 기능을 보조도구로 활용한다
기존의 `MediaMTX`(영상 중계) + `백엔드`(인증) 구조 위에 **WebSocket 채널**만 추가하면, 별도의 무거운 솔루션 없이 영상 스트림과 동기화되는 실시간 강의 도구들을 바로 얹을 수 있습니다.

**실시간 강의 도구 아키텍처 (영상 + 데이터 분리 구조)**
영상은 MediaMTX(WebRTC)가 전담하고, 가벼운 인터랙션 데이터는 백엔드 WebSocket(Socket.IO 또는 FastAPI WebSocket)이 브로드캐스팅합니다.

**핵심 강의 기능 및 구현 로직**

1. **실시간 판서 및 레이저 포인터 (Overlay Canvas)**

* **원리** `<video>` 태그 바로 위에 동일한 크기의 투명 `<canvas>` 태그(`pointer-events: none`)를 겹쳐 배치합니다.
* **동기화** 강사 화면의 마우스 좌표 `(x, y)`를 해상도 비율(0.0 ~ 1.0)로 정규화해 WebSocket으로 전송하면, 수강생의 화면 크기(모바일/태블릿/PC)가 달라도 정확한 위치에 선이나 포인터가 그려집니다.

2. **실시간 코드 및 터미널 스니펫 공유 (IT/실습 강의 특화)**

* **원리** 영상만 보면 수강생이 코드를 타이핑하기 어렵기 때문에, 강사가 텍스트나 명령어를 입력해 전송하면 수강생 화면 하단에 **원클릭 복사 버튼**이 달린 코드 블록이 즉시 팝업됩니다.

3. **실시간 이해도 체크 (OX 퀴즈 / 퀵 폴)**

* **원리** 강사가 퀴즈를 발행하면 수강생 화면에 선택지가 뜨고, 응답 결과가 강사 대시보드에 실시간 막대그래프로 집계됩니다.

4. **질문 큐(Q&A) 및 손들기**

* **원리** 일반 채팅과 분리된 '질문 탭'을 두어, 강사가 답변 완료한 질문은 체크 표시로 닫을 수 있게 관리합니다.

**기술 스택별 연동 방식**

* **Python (FastAPI) 선택 시**
내장 `WebSocket` + `ConnectionManager` 클래스로 방(Room) 단위 브로드캐스팅 구현 (별도 라이브러리 불필요)
* **Node.js 선택 시**
`Socket.IO` 적용 시 네트워크 불안정 환경(로컬 Wi-Fi 순간 끊김)에서 자동 재연결 및 상태 복구 처리가 가장 안정적입니다.

**데이터 전송 페이로드 예시 (JSON)**

```json
{
  "type": "DRAW",
  "payload": {
    "x": 0.452,
    "y": 0.318,
    "color": "#FF3B30",
    "isDragging": true
  }
}

```

어떤 백엔드 프레임워크(예: FastAPI 또는 Node.js)로 구축하실지 알려주시면, **인증 + MediaMTX 연동 + 위 실시간 강의 도구(판서/코드공유/퀴즈)가 포함된 실행 가능한 프로젝트 구조와 핵심 코드**를 바로 구성해 드리겠습니다.
