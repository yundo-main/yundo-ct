# 개발 로드맵

목적: 영상 강의 위에서 **실시간 판서**를 하고, 수강생이 같은 화면을 보며 참여(퀴즈·설문·질문·채팅)하는 강의도구.
그림판(`app/`)은 보조 도구이며 이 로드맵의 중심이 아니다. 현재 상태는 [devlog.md](devlog.md) 참고.

## 현재 위치

| 영역 | 상태 |
|---|---|
| 서버 기능(판서 중계, 퀴즈, 설문, 질문, 채팅/DM, 손들기, 녹화, 다시보기 API) | 구현 완료 (파이썬 + Rust 두 벌) |
| Rust 서버 | 자동 테스트 11건 통과, 브라우저·MediaMTX 실사용 확인 전 |
| 브라우저 화면 | 최소 구현, 실제 사용 확인 전 |
| 판서 | 선 그리기만 가능. **늦게 들어온 수강생은 이전 판서를 못 본다** (서버가 판서를 저장하지 않음) |
| 그림판 앱 | 기본 도구·UI 구현, 파일·테스트는 미완 |

## 단계 한눈에 보기

```text
단계 0  정리·안정화        ──▶ 어디까지 믿을 수 있는지 확정
단계 1  Rust 서버 검증·전환 ──▶ 파이썬 서버 퇴역 (legacy/로 이동 완료)
단계 2  판서 고도화         ──▶ 강의 도구로서 쓸 만한 핵심 가치   ★ 가장 중요
단계 3  녹화·다시보기 정합  ──▶ 영상과 판서가 자동으로 맞음
단계 4  강사용 데스크톱 판서 ──▶ 어떤 화면 위에서든 판서 (시제품 먼저)
단계 5  운영 준비          ──▶ 실제 수강생에게 열기 전 필수
단계 6  그림판 앱 정리      ──▶ 계속할지 결정
```

의존 관계: 0 → 1 → (2, 3 병행 가능) → 4, 5. 단계 5의 보안 항목은 외부에 공개하기 전에 반드시 끝낸다.

## 단계 0. 정리·안정화

**목표**: 지저분한 부분을 정리해 이후 작업의 기준선을 만든다.

- [ ] `auto.crt`/`auto.key` 용도 확인, 개인키는 Google Drive 밖으로 이동
- [ ] `recordings/video/` 위치를 프로젝트 밖으로 (MediaMTX 실행 위치 또는 `recordPath` 지정)
- [x] 8765 포트는 Rust 서버가 쓴다(파이썬 서버는 `legacy/`로 이동, 필요하면 같은 포트에서 하나만 실행)
- [x] 미사용 tkinter 코드는 `legacy/tkinter-paint/`로 이동
- [x] 테스트가 실제 채팅 로그를 오염시키는 문제 수정, 옛 흔적(`c5`, `h1`)은 `legacy/test-data/`로 이동
- [ ] `admin` 역할 동작 확정: 퀴즈 집계·손들기 수신, 녹화 자동 종료 (양쪽 서버에 반영)

**완료 기준**: 테스트를 돌려도 실제 데이터 폴더가 변하지 않고, 역할별 권한 표가 문서에 있다.

## 단계 1. Rust 서버 검증·전환

**목표**: 브라우저·영상까지 포함해 Rust 서버가 파이썬 서버를 대체할 수 있음을 확인한다.

- [ ] Rust 서버를 띄우고 브라우저 2개(강사/수강생)로 판서·퀴즈·설문·채팅·DM·녹화 수동 점검
- [ ] MediaMTX와 연동: 강사 송출(WHIP) → 수강생 시청, 인증 훅 동작
- [ ] 접속자 수십~수백 명 부하 시험 (WebSocket 클라이언트 스크립트), 판서 메시지 지연 측정
- [x] 파이썬 서버와 같은 시나리오 테스트로 동작 일치 확인 (별도 점검표는 만들지 않음)
- [x] 파이썬 서버 퇴역 → `legacy/python-server/`
- [ ] 실행 방법을 하나로 정리 (단일 실행 파일 + `mediamtx` + 설정 파일)

**완료 기준**: 파이썬 없이 Rust 서버 + MediaMTX만으로 한 차례 모의 강의를 끝까지 진행할 수 있다.

## 단계 2. 판서 고도화 ★

**목표**: "선 몇 개 긋는 데모"에서 "수업에 실제로 쓰는 판서"로 올린다. 현재 가장 큰 공백이다.

2-1. **프로토콜 개선 (먼저 해야 함)** — 늦은 입장자 판서 전달 완료(devlog 22)
- [ ] 점 단위 `DRAW` 대신 **획(stroke) 단위**로 모델링: `STROKE_START / POINT / END`, 획마다 id·도구·색·굵기
- [ ] 서버가 현재 판서 상태를 보관하고, **늦게 입장한 사람에게 `STATE`로 전달**
- [ ] 판서 메시지 빈도 제한·좌표 간소화로 네트워크 부담 줄이기
- [ ] 수신 측 화면 크기 변화(회전, 창 크기)에도 다시 그리기

2-2. **강사 도구**
- [ ] 펜 / 형광펜 / 지우개 / 직선·사각형·원 / 레이저 포인터 / 색·굵기 선택
- [ ] 실행 취소·다시 실행 (획 단위)
- [ ] 판서 페이지(칠판 여러 장) 넘기기, 빈 칠판 배경 선택
- [ ] 모바일·태블릿(펜 입력, 터치) 대응

2-3. **수강생 쪽**
- [ ] 판서 보기 켜기/끄기, 확대 보기
- [ ] 강사가 허용하면 수강생도 지정된 영역에 판서(선택 기능, 후순위)

**완료 기준**: 수강생이 수업 중간에 입장해도 지금까지의 판서가 보이고, 강사가 실수를 되돌릴 수 있다.

## 단계 3. 녹화·다시보기 정합

**목표**: 영상과 판서·질문 기록이 수동 조정 없이 맞는다.

- [ ] 이벤트 시각을 영상 파일 기준으로 자동 정렬 (MediaMTX 영상 시작 시각과 `REC_START`의 `wall` 시각 비교)
- [ ] 다시보기 페이지에서 MediaMTX 재생 서버(9996) 연동, 임의 지점 이동 시 판서 상태 정확히 복원
- [ ] 녹화 목록·삭제·내려받기 화면 (강사 전용)
- [ ] 판서가 단계 2의 획 모델로 바뀌면 녹화 형식도 맞춰 갱신 (구형 파일 읽기 호환 유지)
- [ ] 채팅·질문 타임라인을 다시보기에 표시

**완료 기준**: 녹화된 강의를 처음부터 끝까지, 중간 이동 포함해 어긋남 없이 다시 볼 수 있다.

## 단계 4. 강사용 데스크톱 판서 (시제품부터)

**목표**: 강사가 어떤 프로그램 화면 위에서든 판서하고, 그 결과가 수강생에게 전달된다.

- [ ] **먼저 시제품**: Tauri로 투명 전체화면 창 + 클릭 통과 전환 + 단축키로 판서 모드 on/off
- [ ] macOS/Windows에서 동작 차이 확인 (전체화면 앱 위 표시, 다중 모니터, 클릭 통과)
- [ ] 시제품이 쓸 만하면 서버 WebSocket 연동(단계 2의 획 프로토콜 재사용)
- [ ] 화면 공유 영상과 좌표 기준을 맞추는 방법 결정 (공유 중인 창/화면 기준 정규화)
- [ ] 안 되면 대안: 브라우저 화면 공유 + 웹 오버레이만 유지

**완료 기준**: 강사가 슬라이드·코드 편집기 위에서 판서하면 수강생 화면에 같은 위치로 보인다. 시제품 단계에서 불가능으로 판명되면 중단하고 대안으로 간다.

## 단계 5. 운영 준비

**목표**: 외부 수강생에게 열어도 안전하고 운영할 수 있게 한다. 공개 전 필수.

보안
- [ ] 계정을 DB로 이동, 비밀번호 해시(argon2 등), 기본 비밀번호(`teacher`/`admin`)와 기본 비밀키 제거
- [ ] HTTPS/WSS 적용 (리버스 프록시 또는 서버 내장), MediaMTX `webrtcAllowOrigins` 도메인 제한
- [ ] 토큰 만료·갱신, 로그인 시도 횟수 제한, WebSocket 메시지 크기·빈도 제한
- [ ] 수강생 이름 중복·사칭 방지 (같은 이름 동시 접속 처리)

운영
- [ ] 방(강의) 생성·관리, 강사별 방 권한
- [ ] 녹화·채팅 로그 보관 기간, 개인정보(이름·질문) 접근 권한·삭제 절차
- [ ] 서버 재시작 시 방 상태 복구 범위 결정 (퀴즈·설문·판서)
- [ ] 로그·모니터링, 배포 방법(실행 파일 + systemd 또는 컨테이너), 백업
- [ ] 접속자가 단일 서버를 넘으면 방 상태 공유 방식 검토 (Redis 등) — 필요해질 때만

**완료 기준**: 기본 비밀번호·비밀키가 남아 있지 않고, 외부 네트워크에서 HTTPS로 한 차례 리허설이 성공한다.

## 단계 6. 그림판 앱 정리

**결정·완료**: 그림판도 Rust(Tauri)로 다시 만들었다 → [../paint-rs/](../paint-rs/README.md). 1~3단계(도구 12종, 글씨, 채우기, 영역 선택, 확대·눈금·격자, 파일 브라우저, 도움말, 닫기 전 저장 확인)를 마쳐 PySide6 앱은 `legacy/pyside6-paint/`로 옮겼다.

**목표**: 그림판 앱을 계속 개발할지 결정하고 정리한다.

- [ ] 판서가 단계 2·4로 해결되므로, 그림판 앱의 역할 재정의 (독립 도구 / 강의 자료 제작용 / 중단)
- [x] 계속한다 → Rust(Tauri)로 전환(위 결정). PySide6 기준 항목은 더 진행하지 않는다
- [x] PySide6 `app/`은 보관용(`legacy/pyside6-paint/`)으로 옮김

**완료 기준**: 그림판 앱의 위치가 문서에 명시되어 있다.

## 우선순위 제안

1. **단계 0 → 1** (며칠): 지금 만든 것이 정말 동작하는지부터 확인한다. 가장 싸고 위험을 가장 빨리 줄인다.
2. **단계 2-1** (판서 프로토콜): 이후 녹화·데스크톱 도구가 모두 이 모델 위에 올라가므로 가장 먼저 설계를 확정한다.
3. 단계 2-2, 3 병행.
4. **단계 4는 시제품만 먼저** 해서 가능 여부를 일찍 알아낸다. 막히면 계획 전체가 바뀌기 때문이다.
5. 단계 5는 공개 일정이 잡히면 그 전에 끝낸다.

## 열린 질문

- 수강생 규모(수십 명? 수백 명?)와 동시 강의 수 — 단계 1의 부하 시험 기준과 단계 5의 구조를 정한다.
- 강사가 쓰는 환경(macOS/Windows, 태블릿 사용 여부) — 단계 2-2, 4의 우선순위를 정한다.
- 수강생도 판서에 참여하는가 — 단계 2-3의 범위를 정한다.
