## 2026-11-13 (9) 마이크 / 오디오 볼륨 게이지

- `web/index.html` 강사 컨트롤에 게이지 2개: 🎤 마이크, 🔊 화면 소리. AnalyserNode로 소리를 읽기만 하고 내보내지 않는다.
- 막대는 -60dB~0dB를 0~100%로 표시, 올라갈 땐 즉시·내려갈 땐 천천히. 색: 초록 → 노랑(-12dB 초과) → 빨강(-3dB 초과, 소리가 너무 큼).
- 송출 전·소리 없음이면 흐리게(idle) 표시. 화면 공유(+캠 오버레이)와 카메라 단독 송출 모두 지원.
- 검증(Chrome 가짜 마이크 + 440Hz 신호): 송출 전 0 → 송출 중 마이크 87%·화면 소리 85%(노랑) → 캠 오버레이 끄면 마이크 0
  → 중지하면 모두 0. 카메라 단독 경로도 마이크 88%. WHIP 요청은 막아 서버에 송출하지 않고 확인.
- 한계: 송출되는 소리만 측정한다. 수강생이 받는 소리는 MediaMTX iframe(다른 출처) 안이라 측정할 수 없다.
  실제 마이크·실제 시스템 소리, Safari/Firefox는 미확인.

- **버그 수정**: 판서가 1초 안에 사라졌다. `fit()`이 1초마다 `canvas.width`를 다시 대입해 캔버스를 지웠기 때문.
  판서를 0~1 좌표로 기록(`ops`)하고 크기가 실제로 바뀔 때만 다시 맞춰 다시 그리도록 수정. 확인: 1.6초 뒤에도 유지, 크기 변경 후 재그리기, 지우기 동작.
- **서버 `TEXT` 메시지**(강사 전용, 좌표·색·크기·길이 검증, 녹화 대상) 추가 — 파이썬/Rust 양쪽, 테스트 포함(Rust 12건, 파이썬 9건 통과).
  파이썬 서버는 재시작해야 반영된다(8765 포트 프로세스는 아직 이전 코드).
- 파이썬 테스트가 실제 `server/chatlogs/h1`을 읽어 실패하던 문제 수정(임시 폴더 사용). 단, 이전 실행들이 `server/chatlogs/{c5,class1,h1}`에 남긴 테스트 대화 기록은 그대로 있다.

## 11. 강의도구 글씨 도구 · 스크린샷 · 다시보기 글씨

- 강사 화면에 **✏ 펜 / T 글씨** 도구 전환과 글씨 크기 선택을 추가했다. 글씨 도구로 영상 위를 클릭하면 입력 칸이 열리고, 키보드(한글 포함)로 입력해 Enter(또는 다른 곳 클릭)로 확정하면 `TEXT`로 전송되어 모두에게 보인다. Esc는 취소.
- 판서 기록(`ops`)을 선·글씨 공용으로 바꿔서 창 크기가 바뀌어도 글씨가 다시 그려진다. 글씨에는 어두운 윤곽선을 둬 어떤 영상 위에서도 읽힌다.
- **스크린샷**: 모든 사용자에게 📸 버튼이 있다. 영상 + 판서를 1600×900 PNG로 만들어 `screenshot_YYYYMMDD_HHMMSS.png`로 내려받고, 사이드 패널 목록에 파일명·썸네일을 표시한다(클릭하면 확대, 저장, 삭제). 목록은 메모리에만 있어 새로고침하면 사라진다(파일은 내려받은 폴더에 남는다).
- 수강생 시청을 MediaMTX iframe에서 같은 출처의 `<video>`(WHEP)로 바꿨다. iframe은 캡처할 수 없기 때문이다. 송출 전이거나 끊기면 3초마다 재연결한다. 자동재생이 막히면 음소거로 시작하고 화면을 클릭하면 소리가 켜진다.
- `replay.html`이 `TEXT`를 그린다.
- 확인: 헤드리스 Chrome에서 강사 송출 → 수강생 WHEP 수신(영상 재생), 글씨 입력 확정 → 수강생에게 전달, 수강생 스크린샷에 글씨와 영상이 함께 찍힘, 같은 초에 두 번 눌러도 `_2`로 구분, 삭제 동작. 파이썬 9건, Rust 12건 통과.
- 확인하지 못한 것: 실제 마우스·키보드·한글 IME 입력(헤드리스에서 입력 이벤트가 전달되지 않아 DOM 이벤트로 대체), Safari/Firefox, 다시보기 화면의 글씨, 실제 화면 공유.
- 판서 도구를 영상 왼쪽 **세로 팔레트**로 옮겼다(펜/글씨, 색 견본 6개 + 직접 고르기, 글씨 크기, 지우기). 강사에게만 보이고, 폭 860px 이하에서는 영상 위에 가로로 놓인다. 헤드리스 Chrome 화면으로 배치와 색 선택을 확인했다.

## 12. UI 개선 (강의도구 웹·입장·다시보기·그림판)

- **웹 공통**: 색을 변수(디자인 토큰)로 정리하고 **다크 모드** 추가. 기본은 시스템 설정을 따르고, 헤더의 ◐ 버튼으로 자동/밝게/어둡게를 바꾼다(선택은 브라우저에 저장, 다시보기 화면과 공유).
- **강의도구 화면**: 사이드 패널을 **탭**(채팅·질문·퀴즈·설문·스크린샷·참여자)으로 재배치하고, 안 보는 탭에 새 내용이 오면 빨간 점을 표시한다. 송출 컨트롤은 그룹별로 정리했고, 영상이 없을 때 안내 문구를 보여 준다. 사이드는 스크롤 시 따라온다.
- **입장 화면**: 방 이름을 헤더에서 입장 카드 안으로 옮겼다. 입장 후에는 헤더에 방 이름만 표시한다.
- **모바일·태블릿**: 1000px 이하는 1열, 700px 이하는 영상 → 팔레트(가로) → 컨트롤 → 탭 순서. 강사 화면은 `touch-action:none`으로 터치 판서 시 화면이 같이 스크롤되지 않게 했고, 버튼은 36px 이상으로 키웠다.
- **다시보기**: 같은 디자인·다크 모드·모바일 레이아웃으로 정리.
- **그림판 앱**: 보기 ▸ 화면 테마(시스템/밝게/어둡게). 스타일을 테마 표(`THEME_LIGHT/DARK`)로 분리해 다시 적용하는 구조로 바꿨고, 선택은 `QSettings`에 저장한다. 하단 상태줄의 "칠판" 라벨이 안내 문구와 겹치던 것도 고쳤다. 테스트 20건 통과.
- 확인: 헤드리스 Chrome 화면(데스크톱 밝게·어둡게, 390px 모바일, 입장 화면)과 Qt 오프스크린 렌더링을 눈으로 확인. 실제 폰/태블릿 터치, Safari/Firefox, macOS 실제 다크 모드 연동은 확인하지 못했다.

## 13. 아이콘 정리 + 채팅 파일 첨부

- **아이콘**: 글꼴마다 모양이 다른 이모지·글자 기호(📷 🖥 🪟 ✎ ◒ ▩ …)를 모두 선 아이콘으로 교체했다. 웹은 한 곳에 모은 SVG 아이콘 묶음(`<symbol>`)을 쓰고 색은 테마를 따른다. 그림판 도구 12개도 SVG로 직접 그려 테마 색(선택 시 강조색)으로 렌더링한다(테마를 바꾸면 다시 그림). 토스트 문구의 이모지도 제거.
- **채팅 파일 첨부**(양쪽 서버 동일): `POST /api/upload/{room}`(본문=파일 바이트, 20MB, 실행 파일 형식 거부, 입장한 사람만) → 방 전원에게 `CHAT`+`file`. `GET /api/files/{room}/{id}/{이름}`은 항상 내려받기(attachment, nosniff)이고 이미지만 `inline=1` 미리보기를 허용한다. 파일 이름은 경로·특수문자를 제거하고 100자로 자른다. 첨부 기록은 채팅 로그에 남아 재입장/재시작 후에도 복원된다.
- 웹 UI: 채팅 입력 옆 클립 버튼, 채팅 창에 파일을 끌어다 놓기, 업로드 진행률(토스트), 이미지는 썸네일(클릭하면 확대)과 내려받기 카드. DM 대상을 고른 상태에서는 올릴 수 없다(전체 채팅 전용).
- 테스트: 파이썬 10건, Rust 13건(업로드 시나리오 추가), 그림판 20건 통과. 헤드리스 Chrome에서 학생이 txt/png를 올리고 강사 화면에 표시·내려받기·거절 문구를 확인.
- 남은 일: 파일 보관 기간·용량 정리(단계 5), 바이러스 검사 없음, 다시보기에서는 파일 이름만 표시, DM 파일 전송은 미지원.

## 14. 강의자 로그인 분리 + 수강생 화면 공유

- **로그인**: 입장 화면에 **수강생 / 강의자** 탭. 수강생은 이름만, 강의자는 아이디+비밀번호. 서버 `kind`로 강제한다(수강생 탭에서 강의자 아이디를 쓰면 안내 문구와 함께 거절, 강의자 탭은 등록된 계정만 통과). 선택한 탭은 기억한다. 강의자 계정은 `TEACHER_ACCOUNTS`로 여러 명 추가할 수 있다(파이썬·Rust 동일).
- **수강생 화면 공유**(강의자 허용 방식): 수강생이 "내 화면 공유 요청" → 강의자의 접속자 탭에 요청 목록(허용/거절)과 알림 → 허용하면 수강생에게 "공유 시작"이 열려 화면을 선택 → 모두에게 그 화면이 보인다(강의자 영상은 가려지고 "OOO 님이 화면 공유 중" 표시, 판서·스크린샷도 그 화면 위에서 동작). 한 번에 한 명, 발표자나 강의자가 끝낼 수 있고 발표자가 나가면 정리된다.
- 영상은 `{방}__share` 경로로 올라가며 MediaMTX 인증 훅이 현재 발표자에게만 publish를 허용한다. 시청 코드는 `watcher()`로 일반화해 강의 영상과 공유 영상이 같이 쓴다.
- 테스트: 파이썬 12건, Rust 15건(로그인 구분·공유 흐름·권한 추가). 헤드리스 Chrome에서 강의자 1 + 수강생 2로 요청 → 허용 → 공유(가짜 화면) → 강의자·다른 수강생 화면에서 영상 픽셀 확인 → 강의자 종료 → 거절 흐름까지 확인.
- 한계/미확인: 실제 화면 선택 창·실제 화면 공유, 허용 취소 시 서버 쪽 강제 끊기 없음(클라이언트가 스스로 끊음), 공유 영상 소리, 모바일 브라우저(대부분 화면 공유 미지원), 녹화 영상에 공유 경로가 별도로 저장됨.

## 15. 판서 배경 선택

- 강의자 팔레트에 **배경** 선택(영상 / 흰색 / 칠판(초록) / 검정 / 모눈)을 추가했다. 영상 위에 쓰던 기존 방식은 "영상"이고, 나머지는 영상을 가리는 빈 칠판이다. 바꾸면 모두에게 같은 배경이 보이고(`BOARD_BG`, 강의자 전용·값 검증), 늦게 입장한 사람도 현재 배경을 `STATE.boardBg`로 받는다. 녹화되고 다시보기에서도 재현된다. 스크린샷에도 배경이 반영된다(빈 칠판이면 영상은 그리지 않음).
- 칠판 색(#2d4a3e)은 그림판 앱의 "칠판 초록"과 같다. 배경을 바꿔도 이미 쓴 판서는 지워지지 않는다.
- 테스트: 파이썬 13건, Rust 16건. 헤드리스 Chrome에서 강의자가 바꾸면 수강생 화면이 같이 바뀌는 것, 스크린샷에 배경·글씨·선이 찍히는 것, 늦게 입장해도 배경이 맞는 것을 확인. 다시보기의 배경 표시는 확인하지 못했다.
- 아직 없음: 배경을 바꿀 때 어두운 칠판에서 안 보이는 펜 색 자동 보정(그림판 앱에는 있음), 늦게 입장한 사람이 이전 판서를 못 보는 문제(로드맵 2-1).

## 16. 도형·아이콘 올리기

- 판서 팔레트에 **도형**(선, 화살표, 사각형, 원, 사각형·원 채움)과 **아이콘**(체크, 엑스, 별, 물음표, 느낌표, 하트, 전구, 화살표, 깃발, 웃는 얼굴) 도구를 추가했다. 도형은 드래그(놓기 전에는 내 화면에만 미리 보임), 아이콘은 고른 뒤 영상(또는 칠판) 위를 클릭하면 올라간다. 색과 크기 선택(글씨 크기와 공용)을 따른다.
- 새 메시지 `SHAPE`, `ICON`(강의자 전용, 종류·이름은 정해진 값만, 좌표·크기·색은 서버에서 범위·형식 검증). 파이썬·Rust 동일, 녹화되며 다시보기에서도 그려진다. 스크린샷과 창 크기 변경 후 다시 그리기도 지원한다(판서 기록 `ops` 공용).
- 아이콘은 이미지 파일이 아니라 서버가 아는 선 아이콘 모양을 그리는 방식이라 어떤 배경 위에서도 윤곽선으로 읽힌다.
- 테스트: 파이썬 14건, Rust 17건. 헤드리스 Chrome에서 도형 4종과 아이콘 10종이 수강생 화면·스크린샷에 나오는 것, 너무 짧은 드래그는 무시되는 것을 확인(마우스 이벤트는 코드로 만들어 보냄). 다시보기 화면은 확인하지 못했다.
- 없는 것: 올린 도형·아이콘을 선택해 옮기거나 지우는 기능(전체 지우기만 가능), 내 이미지 파일을 판서 위에 올리는 기능.

## 17. 지우개 · 펜 종류/굵기 · 형광펜

- 팔레트 도구를 **펜 / 형광펜 / 지우개 / 글씨 / 도형 / 아이콘**(2열)로 정리하고, **굵기**(가늘게·보통·굵게·아주 굵게)와 **펜 종류**(실선·점선)를 추가했다. 굵기는 도구별 기준값(펜 0.5%, 형광펜 3.5%, 지우개 4%, 화면 높이 대비)에 배율을 곱하며 도형 선에도 적용된다. 형광펜은 노랑으로 시작하고 펜으로 돌아오면 쓰던 색을 되살린다.
- **지우개**는 판서 층(선·글씨·도형·아이콘)만 지우고 영상·배경은 그대로 둔다. 스크린샷은 판서를 별도 층에 그린 뒤 합쳐서 지우개가 배경을 뚫지 않게 했다.
- **형광펜**은 40% 투명한 굵은 선이다. 판서를 점 단위 선분에서 **획(stroke) 단위**로 바꿔서 한 획 안에서는 겹쳐도 농도가 같고(다른 획과 겹치면 진해짐), 점선 모양도 이어진다. 이는 로드맵 2-1의 획 모델로 가는 첫걸음이다(서버 저장·늦게 입장한 사람에게 전달은 아직).
- 프로토콜: `DRAW`에 `mode`(pen/dash/highlight/erase)와 `w`(굵기 비율)가 추가되고, `SHAPE`에도 `w`가 추가된다. 서버가 `DRAW` 전체를 검증한다(좌표·굵기 범위, 색 형식, 종류는 정해진 값). 예전 클라이언트·기록(`mode`/`w` 없음)은 기본 펜으로 처리된다. 파이썬·Rust 동일, 다시보기도 같은 방식으로 다시 그린다.
- 테스트: 파이썬 15건, Rust 18건. 헤드리스 Chrome에서 펜 굵기 2종, 점선, 형광펜(투명도 40%, 겹침), 지우개가 판서만 지우고 스크린샷의 칠판 배경은 남는 것, 수강생 화면 동기화, 다시보기에서 지우개·예전 형식 재생을 확인(마우스 이벤트는 코드로 보냄). 실제 마우스·태블릿 펜 입력감은 확인하지 못했다.
- 한계: 지우개는 지나간 픽셀을 지우는 방식이라 획 단위 삭제가 아니다. 지우개 커서 크기 표시 없음. 펜 압력 감지 없음.
- "Produced by yundo" 표기: 웹 화면(입장·강의·다시보기) 하단, 그림판 상태줄과 도움말 정보 탭.

## 18. Rust 서버로 전환, 파이썬 코드는 legacy로 이동

- **전환**: 강의도구 서버는 Rust(`server-rs/`) 하나가 맡는다. 8765 포트의 파이썬 서버를 내리고 Rust 릴리스 빌드를 같은 포트에서 실행했다. MediaMTX 인증 훅 주소도 그대로 8765라서 설정 변경이 필요 없었다.
- **이동(삭제 아님)**: 파이썬 서버 코드·테스트·의존성은 `legacy/python-server/`, 예전 tkinter 그림판과 그 테스트는 `legacy/tkinter-paint/`, 옛 테스트가 남긴 대화 기록(`c5`, `h1`)은 `legacy/test-data/chatlogs/`로 옮겼다. 옮긴 파이썬 서버는 새 위치에서 테스트 15건이 그대로 통과한다(화면 경로만 새 위치에 맞게 수정). 필요하면 [legacy.md](legacy.md)대로 다시 실행할 수 있다.
- **문서**: `server/README.md`를 `docs/server-api.md`(API·메시지 규약, Rust 기준)로 옮기고, `readme.md`·`plan.md`·`roadmap.md`(단계 0·1 항목 체크)·`server-rs/README.md`와 코드 주석의 경로를 고쳤다. `docs/legacy.md` 추가.
- **빌드 폴더 설정 위치 변경**: `.cargo/config.toml`(빌드 산출물을 Google Drive 밖 `~/.cache`로)을 `server-rs/`에서 프로젝트 루트로 옮겼다. 루트에서 `--manifest-path server-rs/Cargo.toml`로 빌드하면 이전 위치의 설정이 적용되지 않아 `server-rs/target`(약 1GB)이 Drive 안에 생기는 문제가 있어서(이번 작업 중 한 번 발생, 삭제함) 루트에서도 적용되게 했다.
- **검증(실제 브라우저, Rust 서버)**: 헤드리스 Chrome으로 강의자 1 + 수강생 2를 띄워 확인했다 — 강의자 탭/수강생 탭 로그인 구분, 수강생 화면 공유(요청→허용→공유→다른 사용자 화면에서 영상 픽셀 확인→종료→거절, MediaMTX 인증 훅 포함), 채팅 파일 업로드·내려받기·거절 규칙, 판서 배경, 도형 4종·아이콘 10종, 펜 굵기·점선·형광펜·지우개와 스크린샷, 다시보기 재생, 글씨 입력, 수강생 영상 시청(WHEP)과 스크린샷. 자동 테스트는 Rust 18건 통과.
- **아직 확인하지 못한 것**: 접속자 수십~수백 명 부하 시험(로드맵 1단계에 남음), 실제 사람의 마우스·키보드·한글 입력기, Windows 환경, 서버 장시간 운영.
- 그림판 앱(PySide6)은 Python 그대로 `app/`에 있다. Rust 전환 대상은 서버였고, 데스크톱 앱을 Rust로 다시 만드는 것은 별도 작업이다.

## 19. 그림판 Rust(Tauri) 전환 시작

- 결정: 그림판도 Rust로 전환한다. UI 방식은 **Tauri**(Rust + 웹 화면), 범위는 **핵심부터 단계적으로**. PySide6 앱(`app/`)은 새 앱이 기능을 따라잡을 때까지 그대로 두고, 그때 `legacy/`로 옮긴다.
- `paint-rs/` 추가(`ui/index.html` + `src-tauri/`). **1단계 구현**: 연필, 지우개, 색(팔레트 12색 + 직접 선택), 굵기(슬라이더·숫자·미리보기), 실행 취소/다시 실행(획 단위), 새로 만들기(크기 지정), PNG 열기/저장/다른 이름으로 저장(Rust의 파일 대화상자와 파일 입출력), 칠판 색 라디오 6종, 라이트/다크/자동 테마, 단축키.
- Rust 쪽 명령 3개(`save_png_as`, `save_png_to`, `open_image`)와 순수 함수(데이터 URL 해석, 확장자 보정, MIME) 단위 테스트 4건 통과. 이전 PySide6 앱과 달리 칠판 색을 바꿔도 그린 그림이 변하지 않는다(그림 층과 배경 분리).
- 확인: 화면 로직은 헤드리스 Chrome에서 Tauri 명령을 흉내 내 확인(그리기, 지우개가 열어 둔 이미지도 지움, 실행 취소/다시 실행, 칠판 색 바꿔도 획 유지, 저장 합성 결과의 배경·투명, 저장/다시 저장 호출 순서, 열기 후 크기 변경, 새로 만들기 대화상자, 변경 사항 버리기 확인, 단축키). 실제 Tauri 앱을 띄워 창이 열리고 제목이 맞는 것까지 확인(창 화면을 직접 보지는 못함, 실제 파일 대화상자·저장도 직접 눌러 보지 못함).
- 이 작업 중 찾은 버그: 길이 0인 선(클릭만 한 점)은 캔버스가 그리지 않는다. 새 그림판뿐 아니라 **웹 판서(펜·형광펜·지우개 한 점 클릭)와 다시보기에도 같은 문제**가 있어 함께 고쳤다.
- 예정: 2단계(직선·사각형·타원, 글씨, 채우기, 스포이트, 영역 선택), 3단계(확대·눈금·격자·파일 브라우저·도움말·닫기 전 저장 확인).

## 20. 그림판(Rust/Tauri) 2단계

- 추가: **브러시**(부드러운 가장자리), **직선·사각형·타원**(드래그, 놓기 전 미리보기, Shift로 45도·정사각형·정원, 도형 채우기 옵션), **텍스트**(클릭해서 입력 칸이 열리고 글꼴·크기 선택, Ctrl+Enter/바깥 클릭 확정, Esc 취소), **색 채우기**(이어진 영역, 가장자리 오차 허용), **색 선택**(보이는 색 = 그림 층 + 칠판 색), **선택**(점선 영역)과 Delete로 선택 삭제, **영역 삭제** 도구. PySide6 앱의 도구 12종과 같아졌고 단축키도 같다(P B E L R O T F I S D).
- 내부: 그린 내용을 순서대로의 기록(획·도형·글씨·채우기·삭제)으로 보관하고 다시 그려서 실행 취소/다시 실행을 한다. 미리보기·선택 표시는 별도 위 캔버스(`#ov`)에 그려서 그림 층을 건드리지 않는다.
- 확인(헤드리스 Chrome): 도형 외곽선·채움·타원·Shift 스냅, 채우기가 선에서 멈추고 취소/다시 실행 가능, 스포이트(그림 색·칠판 색), 브러시 가장자리 투명도, 영역 삭제와 취소, 텍스트 확정(두 줄·한글 문자열)·취소·바깥 클릭 확정·취소 시 사라짐, 저장 합성에 채우기 포함. Rust 단위 테스트 4건 통과.
- 확인하지 못한 것: 실제 한글 입력기로 타이핑, 실제 마우스·펜, 실제 Tauri 창에서의 화면(위 확인은 같은 화면을 브라우저에서 돌린 것).
- 시험 중 고친 것: 단축키 처리기가 이벤트 대상이 `window`일 때 예외를 던질 수 있어 방어 코드 추가.
- 남은 3단계: 확대/축소, 눈금, 격자, 파일 브라우저, 도움말, 창 닫기 전 저장 확인.

## 21. 그림판(Rust/Tauri) 3단계 완료, PySide6 앱은 legacy로 이동

- **추가**: 확대/축소(25~400%, 슬라이더·버튼·Ctrl+휠·Ctrl+=/-/0, 창에 맞춤, 200% 이상은 픽셀이 보이게), **눈금**(px·cm·mm, 스크롤·확대에 따라감), **격자**(간격 선택, 저장 이미지에는 안 들어감), **파일 브라우저**(Ctrl+B, 폴더 이동과 이미지 열기, Rust `list_dir`/`read_image`), **도움말**(F1: 사용법·단축키·정보), **창 닫기 전 저장 확인**(저장하고 닫기/저장 안 함/취소).
- 닫기 확인 설계: Rust가 `CloseRequested`의 첫 요청을 막고 `close-requested` 이벤트를 화면에 보내며, 화면이 `quit_app`/`close_cancelled` 명령으로 답한다. 화면이 멈춰도 두 번째 닫기는 그대로 닫히게 해서 창이 안 닫히는 상황을 막았다(`should_block_close`, 단위 테스트). 이를 위해 `capabilities/default.json`(`core:default`)을 추가했다.
- **확인**: 화면 로직은 헤드리스 Chrome(Tauri 명령 가짜)로 확인 — 확대 후에도 클릭 좌표가 맞음, 확대 한계, 눈금 그려짐·단위 변경·숨김, 격자 켜기와 확대 시 간격, 파일 브라우저 이동/열기/위 폴더, 변경 사항이 있을 때 열기 전 확인, 도움말 탭, 닫기 흐름 4가지(변경 없음 → 종료, 취소, 저장 안 함, 저장하고 종료). Rust 단위 테스트 7건 통과(폴더 목록 필터·정렬, 이미지 읽기, 닫기 결정 포함). **실제 Tauri 앱을 띄워 창의 닫기 버튼을 눌러 프로세스가 종료되는 것까지 확인**했다(변경 없는 경우).
- 시험 중 고친 버그: 도구를 바꾸면 격자·확대 표시용 클래스가 지워지던 것(도구 클래스만 갈아끼우도록 수정).
- **이동**: PySide6 그림판(`app/`, `main.py`, `tests/`, `assets/`, `requirements.txt`)을 `legacy/pyside6-paint/`로 옮겼다(새 위치에서 테스트 20건 통과). 이에 맞춰 `readme.md`를 Rust 기준으로 새로 쓰고 `docs/legacy.md`를 `docs/legacy.md`로 바꿔 세 가지 이전 코드의 실행 방법을 모았다.
- **PySide6 앱에서 옮기지 않은 것**: 어두운 칠판에서 안 보이는 펜 색을 자동으로 흰색으로 바꾸는 기능, 글꼴 패널의 일부 세부 동작. 실제 한글 입력기와 마우스·펜 입력, 닫기 확인에서 변경 사항이 있는 경우의 실제 창 동작은 직접 확인하지 못했다.

## 23. 그림판: 입력한 글씨 선택·이동
- 선택 도구(S)로 글씨를 누르면 파란 점선 상자로 선택되고, 끌어서 옮긴다. 글씨 위에 마우스를 올리면 커서가 이동 모양으로 바뀐다.
- 이동은 `{k:"m"}` 기록으로 남아 실행 취소/다시 실행이 된다. 글씨 자체는 바뀌지 않고 `replay()`가 이동량을 더해 그린다.
- 헤드리스 Chrome으로 확인: 이동 후 옛 자리 비고 새 자리에 그려짐, 취소하면 원위치, 다시 실행하면 이동.
- 한계: 글씨를 다시 편집(내용 수정)하거나 선택한 글씨만 삭제하는 기능은 아직 없다. 웹 강의도구의 글씨는 이동되지 않는다.

## 24. 그림판: 이동 도구, 클립보드 복사 버튼
- **이동 도구(M)**: 글씨뿐 아니라 도형·펜 획도 눌러서 끌면 옮겨진다(지우개 획, 채우기, 영역 삭제는 제외). 이동은 `{k:"m"}` 기록이라 실행 취소/다시 실행이 된다. 선택 도구의 글씨 이동은 그대로 둔다.
- **클립보드 복사 버튼**(Ctrl+Shift+C): 칠판 색을 합친 그림을 PNG로 클립보드에 넣는다. 선택 영역이 있으면 그 부분만 복사한다.
- 확인: 헤드리스 Chrome에서 도형·획 이동과 취소, 클립보드 쓰기 호출(가짜)로 확인. 실제 Tauri 창의 시스템 클립보드는 확인하지 못했다(WKWebView 권한에 따라 실패할 수 있고, 그때는 안내 메시지가 뜬다).

## 25. 웹 강의도구: 캡처 → 클립보드
- 스크린샷 탭에 "캡처 → 클립보드" 버튼을 추가했다(영상+판서를 PNG로 클립보드에 복사, 파일은 만들지 않음). 목록의 각 스크린샷에도 "복사" 버튼을 넣었다.
- 브라우저 제한: 클립보드 이미지 쓰기는 https 또는 localhost 주소에서만 되고, 그 외에는 안내 메시지를 띄운다. 헤드리스 확인은 하지 않았고 페이지 반영(서버 재시작)만 확인했다.

## 26. 웹 강의도구: 캡처 버튼을 팔레트로
- 팔레트(배경 아래, 편집 위)에 "캡처" 그룹을 추가했다: 저장(캡처 후 파일 저장+목록 추가), 복사(캡처 후 클립보드). 스크린샷 탭은 목록 보기·삭제와 수강생용 버튼으로 유지한다(팔레트는 강의자 전용).
- 확인: 헤드리스 Chrome에서 강의자 로그인 후 두 버튼이 보이고, 저장은 목록에 타임스탬프 파일이 생기며, 복사는 클립보드 쓰기(가짜)에 PNG가 전달됨.

## 27. 웹 강의도구: 송출 컨트롤 줄을 무대 폭에 맞춤
- 송출 컨트롤 줄(`#controls`)과 수강생 바(`#studentBar`)가 팔레트 아래까지 가로로 펼쳐지던 것을, 무대와 같은 열(`#stageCol`)에 넣어 무대의 왼쪽 끝·폭에 맞췄다. 팔레트는 왼쪽에 그대로 세로로 길게 있다.
- 확인(헤드리스 Chrome 1400px): 무대 left 132·폭 865, 컨트롤 줄 left 132·폭 865로 일치. 좁은 화면(700px 이하)은 기존처럼 세로로 쌓이는 규칙을 그대로 두었고 직접 확인하지는 않았다.

## 28. 웹 강의도구: 송출 컨트롤을 사각 아이콘 버튼으로
- 카메라·화면 공유·창 공유·중지·녹화 버튼을 팔레트와 같은 사각(62×58px) 아이콘 위·글자 아래 형태로 바꿨다. 줄 높이도 129px → 105px로 줄었다.
- 녹화 버튼 아이콘이 빨간 점으로 나오지 않던 오류(`href="#i-rec rec"`)도 같이 고쳤다.
- 확인: 헤드리스 Chrome 스크린샷. 송출 중·녹화 중 상태의 모양은 확인하지 못했다.

## 29. 캠 오버레이 기본 크기 축소
- 캠 너비 비율을 작게/보통/크게 = 16/24/34% → 11/16/24%로 줄였다(기본 "보통"은 24% → 16%, 약 3분의 2). 선택지는 그대로.
- 실제 송출 화면에서의 모양은 확인하지 못했다.

## 30. 퀴즈·설문 결과 저장
- 서버: 퀴즈·설문이 끝나면(또는 끝내지 않고 새로 발행해 대체되면) 결과를 `server/chatlogs/{방}/polls.jsonl`에 한 줄씩 남긴다(시각, 종류, 질문, 선택지, 득표, 응답자 수, 응답자별 선택). 익명 설문은 사람별 선택을 저장하지 않는다. `GET /api/polls/{방}?token=`(강의자만)으로 읽는다.
- 화면: 퀴즈·설문 탭에 "결과 저장 (CSV)" 버튼(강의자 전용). 엑셀에서 한글이 깨지지 않게 UTF-8 BOM 포함.
- 테스트 `poll_results_saved` 추가(서버 테스트 20건 통과). 헤드리스 Chrome으로 설문 종료 후 버튼을 눌러 CSV 내용 확인.
- 한계: 진행 중인 퀴즈·설문은 종료해야 저장된다. 질문과 선택지를 다음 수업에서 다시 불러 쓰는 "문제 보관함"은 없다.
